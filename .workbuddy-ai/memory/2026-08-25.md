- 仅依据 Go 源码梳理了 Agent 上下文压缩：internal/agent/runtime.go 的 Run 在每个 model step 前调用 buildContext；生产 app 使用 rolling-summary v5，RecentTurns=4，默认阈值 60,000 / 硬上限 80,000，模型元数据可动态覆盖预算。策略保留最近完整轮次，旧轮次生成不可信摘要，支持分块/层级合并、摘要缓存、稳定事实校验、失败时整轮安全裁剪；当前轮超限则返回 CurrentTurnTooLargeError。相关测试 go test ./internal/contextmanager ./internal/agent 已通过。
- 复核发现高优先级风险：fitHardLimit 超限时会先丢掉最老的摘要消息，但 runtime 仍持久化该 compaction，后续会跳过原始历史并反复丢摘要；摘要模型没有设置 MaxOutputTokens；摘要调用 Usage/Cost 未进入 RunLimits 的 RecordUsage 预算；摘要分块估算未计入 FormatSummaryInput JSON 包装开销。另有中优先级问题：Ephemeral 与当前消息共用 RunID，过大时可能无法单独丢弃；历史图片在摘要输入中只保留 image 类型而丢弃数据；空 TurnID 时整轮保护不成立。
- 进一步整理了摘要期间的双轨数据流：Session Entry/Compaction 是权威会话树，决定下一次 branch 如何跳过原始消息；SummaryStore 是按 session+source digest+strategy+version+kind 索引的可重建旁路缓存，chunk/merge/final 都可缓存，但通常只有 final summary 回写为 compaction entry。缓存命中不会自动替代 session entry，缓存 miss/损坏可重建，entry 才决定历史覆盖边界。
- 评估 coding agent 工具设计：13 个核心工具加可选的 4 个 LSP 工具，读/搜/改/校验/Git/导航职责整体清晰，权限、重放、输出边界和 artifact 外置设计合理。发现高优先级安全缺口：git_diff 为空 path 时 security boundary 不触发敏感路径审批，可能把敏感文件 diff 暴露给模型；能力缺口包括无受控通用命令或格式化工具、检查计划仅覆盖 Go/Python/Node、无显式 rename/move、git diff 对未跟踪文件信息不足。list_check_plans 与 run_checks 有一定重复，LSP 四个工具是同一实现的模型可用性拆分，edit/replace/apply_patch 的粒度差异合理。
- 梳理工具 boundary 流程：Factory 以 artifactBoundary(最外) -> securityBoundary -> permissionBoundary(最内) -> concrete tool 包装；security 负责敏感路径审批与结果/错误脱敏，artifact 负责大文本结果外置并只留 preview+artifact ref，permission 负责 permission mode/grant/approval 与恢复时再次检查模式；resumableArtifactBoundary 仅在内部实现 ResumableTool 时包装 Resume，并对恢复结果再次外置。Runtime 先记录 sanitized ToolStarted，再执行；普通结果经 boundary 变换后写入 Tool message entry、ToolFinished record 和事件，随后进入下一轮上下文；中断只写 InterruptRequested，不写 Tool result entry，恢复完成后再写入。Progress 只走 event stream，不进入 session message/context。
- 梳理四层工具边界：Factory 顺序为 permission -> security -> artifact，最终调用链为 artifactBoundary -> securityBoundary -> permissionBoundary -> 原始工具；四个 boundary 本身不写 session journal，Runtime 负责 RecordToolStarted/Finished、InterruptRequested、tool Entry 和 Event。security 负责敏感路径审批与结果脱敏，permission 负责模式/授权决策，artifact 负责大结果外置，resumableArtifactBoundary 负责在外置结果的同时保留 Resume 能力。
   7. 复核 SaveArtifact/LoadArtifact 链路：大文本结果在 artifact boundary 超过 64 KiB 时保存完整 JSON 到 coding-artifacts/<sha256>.blob，并将不超过 16 KiB 的 preview、typed details 和 sha256 引用写入 Tool message/journal/context；当前源码没有任何生产路径调用 LoadArtifact，也没有向模型暴露 artifact 读取工具，因此模型只能看到引用和预览，无法按引用取回完整产物。
