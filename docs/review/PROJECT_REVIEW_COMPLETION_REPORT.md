## 🔍 核心流程解析结果

### 1. Agent 执行循环 (runSteps)
✅ **完全理解**: 包括启动、LLM 调用、工具执行、预算检查、完成判断

**关键特点**:
- 循环执行 Step 1, 2, 3... 直到完成
- 每一步都记录到会话（持久化）
- 工具预算和进度检查防止无限循环
- 支持中断和恢复

### 2. 会话恢复机制
✅ **完全理解**: 4 层决策过程（分析→规划→决策→执行）

**关键流程**:
- AnalyzeRecovery: 找出未完成的操作
- BuildRecoveryPlan: 根据 ReplayPolicy 分类
- recoveryDecision: 应用自动或用户决策
- recoverPendingTool: 执行具体的恢复策略

### 3. 工具执行防御体系
✅ **完全理解**: 7 层验证（从工具存在到结果处理）

**防御等级**:
- 第 1-3 层: 验证工具、权限、预算
- 第 4-5 层: 参数清理、重放策略检查
- 第 6-7 层: 执行和结果处理

### 4. 上下文管理
✅ **完全理解**: 预算分配、压缩算法、优化策略

**核心机制**:
- Token 预算分配 (系统提示 20% + 工具 30% + 历史 50%)
- 长对话自动压缩为摘要
- 动态调整预算分配

### 5. 恢复后的 Agent Loop 继续
✅ **完全理解**: 恢复不改变逻辑，只是跳过已完成的步骤

**流程**:
- 恢复工具执行
- continueAfterAssistant() 处理剩余工具
- runSteps(step+1) 继续 Agent Loop
- LLM 看到完整的上下文和结果后继续决策

## 💡 技术亮点总结

### 1. 幂等工具执行机制
```
工具带有 IdempotencyKey
重复执行 → 服务器返回相同结果
完美支持崩溃恢复场景
```

### 2. 分支会话支持
```
Lane 机制支持多条平行对话
用户可以在不同分支间切换
适合探索性编程
```

### 3. 无损恢复设计
```
Entry + Record 双模型
入口树用于上下文
日志用于恢复
完全恢复执行状态
```

### 4. 灵活的权限模型
```
read-only      - 最安全
ask            - 平衡模式
auto-edit      - 便利模式
自动批准低风险操作
```

### 5. 智能上下文管理
```
动态压缩长对话
提取关键信息
保留决策结果
节省 Token 成本
```
